# ADR-0008 契約に書く境界の読み方を 1 つに決める

## Context

契約（`contract.yaml`）は、持ち主・変更の頻度・寿命が違う二者の境界の形を書く（R-1201）。このアプリはサーバを持たず（ADR-0001）、HTTP の API が無い。ユースケースごとに担当が境界を読み分けると、同じものが別の種類で書かれる。本人の方針（2026-10-03）は、保存キーと型を仕様（UC / REQ）から外して契約へ移すこと（OPEN-QUESTIONS OQ-08 の (a)）。

## Decision

境界は次のように読む。全ユースケースで同じに適用し、担当は読み替えない。
- **時間の境界（端末への記録）**: 占い履歴と本日の一枚。`local-store`、`owned: true`。配った版が書いたデータを後の版が読めることが最重要の契約で、フィクスチャは `contracts/fixtures/` に追記のみで置く（R-1202）。フィクスチャと読めることのテストは移行後に `/develop` で作る。
- **端末の共有機能**: シェア画像を渡す先。`device`、`owned: true`（渡す形はこちらが決める）。権限の宣言は要らない。
- **第三者の SDK**: エラー監視サービスと、新しい版の問い合わせ・保持の仕組み。`sdk`、`owned: false`、`source:` に写し取り元。
- **OS・配信の設定**（ホーム画面に置くための宣言、ネイティブのプロジェクト設定、CI の手順）: それ自体が機械可読な正本なので、契約に写さない（R-1203）。
- **アプリの中のモジュールの間**（画面と状態、状態と抽選、生成物の型）: 操作にしない。言語の型が契約で、層の向きは ADR-0009 と trace-check が見る（R-1204）。`internal` は使わない。
- **生成スクリプトの入出力**（編集元・原本 → 生成物）: ホスト上のファイルで、形は生成物の型と、スクリプト自身の書式の確かめが担う。操作にしない。
- 境界を 1 つも越えないユースケースは `operations: {}` と理由つきの `x-no-boundary` で宣言する（R-1206）。
- **端末の機能の判定**（ネイティブのアプリの中かどうか）: 第三者の SDK として `sdk`、`owned: false`。
- **同じ SDK の入口を 2 つのユースケースが使うとき**（保持の登録は、通信なしで使うことと新しい版が届くことの両方の入口）: 操作は 1 つの契約だけが持つ（R-101）。新しい版を届けるユースケースの契約が持ち、もう一方は境界なしの宣言でそれを名指しする。
- **同じ配信元からの分割読み込み**（カテゴリの文章を選んだときに読む）: アプリの中のモジュールの間として扱い、操作にしない。
- **端末の音の出力**（効果音）: 権限も戻り値も失敗の経路も無く、ユースケースにも要件にも現れないので、操作にしない。
- **シェア画像の端末への保存**: 共有機能へ渡す操作の中の振る舞いとして扱い、別の操作にしない。
- **端末への記録の操作の形**: request と response は、コードが外に出している関数の引数と戻り値。端末に残る記録そのものの形は、契約の `schemas` に名前を付けて置き、フィクスチャはその形に従う。保存キーは、書式に置き場が無いので `summary` に書く。
- **失敗の経路**: コードが失敗を外に出さない操作は `errors: []`。外に出す失敗が実在するときだけ、共有の語彙（`docs/_shared/components.yaml` の `errorCodes`）のコードを使う。境界の中で閉じる分岐（取り消し・代わりの手段への切り替え）はエラーにしない。
操作の名前は、コードが外に出している名前に合わせる（検査の決まりで先頭は小文字にする）。外に出している名前が無い操作（本日の一枚の記録の読み書きは部品の中の関数）は、今の内部の名前を仮に使い、移行後に外へ出す（OPEN-QUESTIONS OQ-32）。

## Consequences

- 良い面: 契約が実在する境界だけを持つ。HTTP の操作を作り話で足さない。
- 悪い面: 多くのユースケースが「境界なし」の宣言になり、契約による検査（例の実行）が効くのは端末への記録と共有機能だけになる。時間の境界のフィクスチャが無い間、過去の版が書いた記録を読めることは保証されない。エラーコードの語彙が無く、失敗の経路を契約に書くにはまず語彙を決める必要がある。

## 却下した選択肢

- **アプリの中の境界も `internal` で契約にする**: モジュールの数だけ操作が増え、型と二重になる。小さなアプリでは割に合わない。
- **端末への記録を `sdk`（ブラウザの API）として写す**: 記録の形はこちらが決めるものなので、写し取りではない。
