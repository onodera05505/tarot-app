# ADR-0001 アプリは端末の中で完結させ、バックエンドを持たない

## Context

v2 の要件定義（2026-04）はバックエンド API からカードを取得する構成だった。2026-05-07 のコミット 6bdce81 で、カード 22 枚の内容をアプリに同梱し、抽選も端末の中で行う構成へ移った。`history/2026-08-21.md` の 2. に「アーキテクチャも v2 記載の backend API からフロント完結（local-only）へ移行済み。backend/ は参照用残置」とある。移行を決めた時点の理由は記録に残っていない。

## Decision

アプリは端末の中で完結させる。カードの内容と詳しく占うの文章はアプリに含め、占い履歴と本日の一枚は端末への記録だけに置く。通信が要るのは配信・自動更新・エラーの報告だけにする。
担保: 構造的な門は無い（説得による統制。R-901）。`backend/` は参照用の残骸で、CI は触らない（2026-09-02）。

## Consequences

- 良い面: アカウントも通信も要らずに占える。配信先の費用と運用が小さい。通信なしで動く（GOAL-06）。
- 悪い面: 占い履歴は端末をまたげず、端末のデータが消えれば戻らない。カードの内容を直すたびに版を出し直す必要がある。使われなくなったバックエンドが公開されたまま残っていた（2026-09-02 に削除。`brain/reports/05`）。

## 却下した選択肢

- **記録なし**: 当時の比較は記録されていない（移行時に付した記録）
