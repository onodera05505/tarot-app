# ADR-0010 Android では OS のバックアップと端末間の引き継ぎに、アプリの記録を載せない

## Context

占い履歴と本日の一枚は端末の中だけに置く（ADR-0001）。ところが Android のプロジェクトは作ったときの既定のまま、OS のバックアップを許していた。
この設定では、端末の記録が利用者自身の Google のバックアップに入り、機種変更のときに新しい端末へ引き継がれうる。運営者は受け取らないが、
「記録は端末の外へ出ない」というストアへの説明と、字義では食い違う。

2026-10-03、本人が「ストア申告を考えたセキュリティにする」と決め、続けて「端末引き継ぎは消してもいい」と答えた（`brain/PREMISES.md`）。
ストアのプライバシーの申告を、できるだけ単純に言い切れる形にするのが意図。

## Decision

Android のアプリでは、OS のクラウドへのバックアップにも、端末から端末への引き継ぎにも、アプリの記録を載せない。
設定の正本は Android の設定ファイル（`frontend/android/app/src/main/` のマニフェストと、そこから指すバックアップの規則）で、値はここへ写さない。
担保: `frontend/tests/android-backup.test.ts` が設定ファイルを読んで確かめる。実機での確認（機種変更やアプリの入れ直しで記録が戻らないこと）は未実施で、
Android の実機確認（保留中）の項目に加える。

Web 版（ブラウザとホーム画面のアプリ）は対象外。ブラウザの記録の扱いはブラウザと OS が決め、アプリからは変えられない。

## Consequences

- 良い面: 「占い履歴は端末の中だけにあり、運営者にも OS のバックアップにも渡らない」と説明できる。申告の前提がアプリの設定だけで閉じる。
- 悪い面: 機種変更やアプリの入れ直しで、占い履歴と、その日に開封した本日の一枚が消える。引き継ぎたい利用者のための手段は無い。
- 引き継ぎを後から用意するなら、利用者が自分で書き出して読み込む機能として、要件から起こす（OS のバックアップを黙って戻さない）。

## 却下した選択肢

- **既定のまま（バックアップを許す）**: 運営者は受け取らないので申告の対象ではないが、「端末の外へ出ない」と言い切れず、説明に但し書きが要る。本人が引き継ぎは無くてよいと判断した。
- **クラウドへのバックアップだけ止め、端末間の引き継ぎは残す**: 引き継ぎの便利さは残るが、記録が端末の外へ出る経路が 1 つ残り、説明が 2 段になる。
