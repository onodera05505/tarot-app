# ADR-0011 新しい版は自動で入れ替えるが、占いの途中では占いが終わるまで待つ

## Context

ADR-0003 は「手動の更新をさせない」ために、新しい版が分かった時点で占う人の操作なしに入れ替えると決めた。その帰結として、占いの途中（儀式の中、カードを引いている間、占い結果を読んでいる間）でも画面が読み込み直され、途中の占いが消えていた（OQ-28 の 1）。
2026-10-03 に本人が「仕様と食い違う欠陥は直す」と裁定し、2026-10-19 に「見えた穴は直して」と指示した。REQ-083・REQ-128。

## Decision

手動の更新をさせない方針は変えない。入れ替えのタイミングだけを変える: 新しい版があると分かったとき、占う人が占いの途中でなければ従来どおりすぐ入れ替え、占いの途中なら途中の占いを消さずに続けさせ、占いの途中でなくなってから入れ替える。
「占いの途中」は UC-008 の表の前書きが定義する（儀式の中・占い状態 drawing・drawn の占い結果を示している間）。詳しく占うのカテゴリと質問に答えている間と、本日の一枚の開封中は含めない（前者は回答が消えるが短く、後者は記録が済んでいて消えない。含めるかは次の判断）。
実現には、保持の仕組みに「新しい版が届いた」を受け取り、アプリの側で「入れ替える」を呼ぶ形（UC-008 の契約の `onNeedRefresh`・`updateSW`）が要る。設定の正本はビルドの設定（R-1203）で、ここへは写さない。
担保: REQ-128 の分割クラス（入口を起動するテスト）。実ブラウザでの入れ替えの確認は通しテストの環境が「古い版の保持」と「新しい版を返す配信元」を持てるようになってから（OQ-35 の 4）。

## Consequences

- 良い面: 占いの途中で画面が消えない。直した版が届く速さは、占いをしていない利用者には変わらない。
- 悪い面: 占いの途中の利用者には新しい版が届くのが遅れる（占いを終えるまで）。占い結果を表示したまま長く置くと、その間は古い版のまま。入れ替えの判断がアプリの側に入るので、保持の仕組みの設定とアプリの両方を合わせて変える必要がある。
- ADR-0003 の「悪い面」の 1 つ目（占いの途中でも入れ替わる）は、この決定で解消する。ほかの内容（自動で入れ替える・ビルド識別子を示す・手動更新を退ける）はそのまま引き継ぐ。

## 却下した選択肢

- **次にアプリを開いたときまで待つ**: もっと保守的だが、占い結果からトップへ戻った利用者が古い版のまま次の占いを始めてしまい、直した版が届く機会が減る。占いの途中でなくなった時点で入れ替えるほうが、手動更新をさせない方針に近い。
- **占いの途中でも入れ替えるが、途中の占いを保存して復元する**: 占い状態を端末に残す必要があり、ADR-0001（端末に残すのは占い履歴と本日の一枚だけ）の範囲が広がる。復元の整合（儀式の段階・演出の途中）も難しい。
