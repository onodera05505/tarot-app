## 1. プロジェクト概要

リアルな占い体験を提供するワンオラクル（1枚引き）タロット占いアプリ。対面で占い師にカードを切ってもらっているような、儀式性のある多段階のシャッフル演出を最大の特徴とする。

最終ゴールは iOS / Android ストアでの公開（Web → PWA → Capacitor の順でラップ。フルリライトはしない）。現フェーズはその前段の「アプリ自体の磨き込み」であり、ゲスト利用・ローカル完結で完成度を高める。

### 1.1 検証したい体験価値（v2 から継承）

- ユーザーが「もう一度引きたい」と感じる体験になっているか
- 結果（カード・キーワード・解説）に納得感を得られるか
- 演出が起動〜結果表示までの離脱を抑止できているか

## 2. システムアーキテクチャ（v3 で全面変更）

**フロントエンド単独で完結する（local-only）。** ネットワーク API・DB は使わない。

| レイヤー | 採用技術 |
|---|---|
| フロントエンド | React 19 + TypeScript + Vite |
| ルーティング | react-router（BrowserRouter） |
| 状態管理 | zustand（占い進行）。永続データは localStorage 直接利用 |
| アニメーション | Framer Motion |
| PWA | vite-plugin-pwa（autoUpdate、オフライン動作） |
| エラー監視 | Sentry（本番かつ DSN 設定時のみ初期化） |
| カードデータ | `frontend/data/cards.md`（編集用一次データ）→ `pnpm gen:cards` → `frontend/src/data/cards.ts`（自動生成、直接編集禁止） |

- 旧 backend（Hono on Cloudflare Workers + Prisma）は**参照用の残骸**であり、本番デプロイもフロントからの呼び出しも行わない。`frontend/src/lib/api.ts` は旧 API のシグネチャを模した Promise ラッパーで、抽選ロジック（Fisher–Yates・正逆 50%）をローカル実行する
- デプロイは GitHub Actions（main push）→ Cloudflare Pages のみ

## 3. スコープ定義

### 3.1 現フェーズに【含める】もの

- 大アルカナ 22 枚のデータ完備（正逆キーワード + 正逆それぞれの詳細解説文 + WebP 画像）
- トップ画面（動的背景 + 本日の一枚 + 各画面への導線）
- 儀式フローによるワンオラクル（§5.3）
- 詳しく占う（カテゴリ × 質疑応答つきリーディング。§4.4・§5.7）
- 結果表示画面（フリップ演出・キーワード・詳細解説・シェア・**もう一度占う**）
- カード解説の一覧・詳細画面
- 占い履歴（localStorage、最大 100 件）
- PWA（ホーム画面追加・オフライン動作）
- ゲスト利用前提（認証なし）

### 3.2 現フェーズから【除外】するもの（将来フェーズ → §7）

- 小アルカナ 56 枚、複数枚引き（スプレッド）
- ユーザー認証、履歴のクラウド保存
- AI API 連携による詳細リーディング
- 広告・課金（マネタイズ設計は §7.2 に確定済み方針として記録）
- 効果音の本格実装（§7.3）・ハプティクス
- Capacitor ラップとストア申請（§7.1）

## 4. データ仕様

### 4.1 TarotCard

大アルカナ 22 枚（`number` 0〜21、`id` 1〜22）。各カードは以下を持つ:

| フィールド | 内容 |
|---|---|
| `id` / `number` | 連番 ID / アルカナ番号（0=愚者 〜 21=世界） |
| `nameEn` / `nameJa` | 英名 / 和名 |
| `arcanaType` | アルカナ種別（現状は大アルカナのみ） |
| `meaningUpright` / `meaningReversed` | 正位置 / 逆位置のキーワード（カンマ区切り 2〜3 語） |
| `descriptionUpright` / `descriptionReversed` | 正位置 / 逆位置の詳細解説文（各 200 字前後） |
| `imageUrl` | `/cards/major/NN_name.webp`。裏面は `000.webp` |

- プレースホルダー（「未設定」等)を残さない
- 解説文の文体・構造ルールは編集用一次データ `frontend/data/cards.md` の運用に従う

### 4.2 抽選ロジック

- カード種類・正位置/逆位置とも**完全ランダム**（正逆は各 50%）
- 儀式中のユーザー操作（山の順序・山の選択・左右選択）は**結果に一切影響しない**。演出によって納得感を作る（設計判断: 2026-05-02、コミット 24efef6。当初の「左右選択で正逆決定」はユーザー要望で撤回済み。覆すときはこの経緯を読んでから）
- 結果は「ストップ」押下時点で内部的に確定する

### 4.3 localStorage キー

| キー | 内容 |
|---|---|
| `tarot:history` | 占い履歴。最新順、最大 100 件（超過分は古い方から破棄） |
| `tarot:todaysCard` | 本日の一枚。`{ date: 'YYYY-MM-DD', drawn }`。日付が変わると無効 |

### 4.4 詳しく占うデータ（v3.1 で追加）

**設計方針: 合成方式。** 結果文を「カード × 正逆 × カテゴリ × 回答の全組み合わせ」で
書き切ると約 3,600 本になり執筆・保守が破綻するため、以下の部品を組み合わせて
1 つの結果として表示する。

| 部品 | 数 | 分量の目安 |
|---|---|---|
| ベース解釈（カテゴリ × カード × 正逆） | 5 × 22 × 2 = 220 本 | 各 150〜250 字 |
| 質問（カテゴリごとに 3 問、各 3 択） | 5 × 3 = 15 問 | 質問文 + 選択肢ラベル |
| 回答別補足（選択肢ごとに 1 本） | 5 × 3 × 3 = 45 本 | 各 60〜120 字 |

- カテゴリは 5 つ: **仕事 / 友達・恋愛 / 勉強 / お金 / 健康**。
  データ構造はカテゴリ追加が定義ファイルの追加だけで済む形にする
- 編集用一次データは `frontend/data/deep/<カテゴリ>.md`（カード解説 `cards.md` と
  同じ「md を編集 → 生成コマンド → ts 自動生成、直接編集禁止」の運用）
- 生成された各カテゴリのデータは**カテゴリ選択後に動的 import** し、
  初回ロードのバンドルに含めない（1 カテゴリ約 30KB）
- 文体・構成は `cards.md` の既存解説文の執筆ルールに準拠する

### 4.5 詳しく占うの抽選と結果合成

- カード・正逆の抽選は §4.2 と完全に同一（**質疑応答の回答はカードの抽選に
  一切影響しない**。回答が決めるのは表示する解釈テキストの選択のみ）
- 結果画面の合成: 「ベース解釈（引いたカード × 正逆 × 選択カテゴリ）」+
  「回答別補足 3 本（3 問それぞれの選択肢に対応）」を表示する

## 5. 画面仕様

### 5.1 ルーティング

| path | 画面 |
|---|---|
| `/` | トップ |
| `/shuffle` | 儀式（シャッフル〜向き選択）。通常・詳しく占う共用 |
| `/deep` | 詳しく占う（カテゴリ選択 → 質問 3 問）→ `/shuffle` へ |
| `/result` | 結果表示 |
| `/cards` | カード解説一覧 |
| `/cards/:id` | カード解説詳細（`?orientation=` で正逆の初期表示指定可） |
| `/history` | 占い履歴 |
| `*` | `/` へリダイレクト |

画面遷移はフェードによるルートトランジションを伴う。

### 5.2 トップ画面

- ロゴ「Tarot」+ サブタイトル「あなたの「いま」を1枚に映す。」+ パーティクル動的背景
- **本日の一枚**: 未開封時は裏向きカード +「タップして開く」。タップでフリップ演出とともにその日の 1 枚（正逆あり）を確定し、日付キーでキャッシュ。1 日 1 回のみ。開封済みはカード画像＋名前＋正逆を表示し、タップでそのカードの解説詳細へ
- ボタン: 「スタート」（占い状態をリセットして `/shuffle` へ）／「詳しく占う」（リセットして `/deep` へ）／「カード解説を見る」／「占い履歴を見る」

### 5.3 儀式フロー（`/shuffle`）

フェーズを以下の順に進む。各フェーズの画面内文言は「」内の通り。

| # | フェーズ | 内容 | ユーザー操作 |
|---|---|---|---|
| 1 | intent | 「占うことを思い浮かべてください」 | 「シャッフルへ」押下 |
| 2 | shuffling | 22 枚が 3D の山として舞い、混ざり続ける（サブフェーズ自動巡回）。「シャッフルを止めてください」 | 「ストップ」押下（**この瞬間に結果が内部確定**） |
| 3 | merging | 1 山に集約（自動） | なし |
| 4 | split3 | 3 山に分割。「積み上げる順番を指定してください」 | 3 山を 1→2→3 の順にタップ + 「決定」 |
| 5 | stacking3 | 指定順に積み重ね（自動）。指定順は山の描画順序に実際に反映される | なし |
| 6 | split2 | 2 山に分割。「どちらかの山を選択してください」 | 片方をタップ + 「OK」 |
| 7 | stacking2 | 選んだ山を上にして積み重ね（自動） | なし |
| 8 | rotating | 反時計回り 90° に寝かせて拡大（自動） | なし |
| 9 | orienting | 「どちらを上にするか選択してください」 | 「左」/「右」押下（演出のみ、結果に影響しない） |
| 10 | transitioning | 選択に応じて回転し `/result` へ遷移 | なし |

### 5.4 結果表示画面（`/result`）

- カードのフリップ演出（rotateY、逆位置は 180° 回転で表示）。フリップ時に効果音（§7.3 の暫定実装）
- 表示: カード画像（タップで拡大モーダル）／カード名／正位置・逆位置／キーワード一覧／正逆に応じた詳細解説文
- ボタン:
  - 「この結果をシェア」— Canvas で 1080×1920 の画像を生成し Web Share API で共有（非対応環境はダウンロードにフォールバック）
  - **「もう一度占う」— 占い状態をリセットして `/shuffle` へ**（※v2 からの要件。現状未実装 → §6）
  - 「トップへ戻る」— 占い状態をリセットして `/` へ
- 直接 URL 到達など占い結果がない状態（idle）では `/` へリダイレクト

### 5.5 カード解説一覧・詳細（`/cards`, `/cards/:id`）

- 一覧: 22 枚をアルカナ番号順に表示。タップで詳細へ
- 詳細: カード画像・名前・正逆それぞれのキーワードと解説文。クエリ `orientation` で初期表示の正逆を指定できる

### 5.6 占い履歴（`/history`）

- `tarot:history` の内容を新しい順に一覧表示（日時・カード・正逆）
- 全削除操作を提供
- 記録タイミングは占いの結果確定時（自動）。本日の一枚は履歴に**含めない**
- 詳しく占うの結果はカテゴリ名を添えて記録・表示する（通常占いは従来通り）

### 5.7 詳しく占う（`/deep`、v3.1 で追加）

トップの「詳しく占う」から入る、カテゴリ特化のリーディング。

**フロー: カテゴリ選択 → 質問 3 問 → 儀式（§5.3 と同一）→ 結果**

1. **カテゴリ選択**: 仕事 / 友達・恋愛 / 勉強 / お金 / 健康 の 5 択。
   選択した時点でそのカテゴリのデータを動的読み込みする
2. **質問**: 選択カテゴリの 3 問を 1 問ずつ表示。各 3 択、タップで次の問へ。
   「戻る」で前の問に戻れる（回答は保持）。3 問目の回答で儀式へ進む
3. **儀式**: 既存の 10 フェーズ（§5.3）をそのまま通る。抽選も §4.2 と同一
4. **結果**: 既存の結果画面の表示（カード・正逆・キーワード）に加えて、
   - カテゴリ名の表示
   - 通常の解説文の代わりに、**ベース解釈 + 回答別補足 3 本**（§4.5）を表示
   - 「もう一度占う」「シェア」「トップへ戻る」は通常占いと共通。
     シェア画像は初期リリースでは通常占いと同一仕様（カテゴリ非表示）

- 途中でブラウザバック等により回答が欠けたまま儀式へ進む経路は作らない
  （質問未完了で `/shuffle` に直接到達した場合は通常占いとして扱う）
- 質問と回答は占いのたびに初期化する（前回の回答を引き継がない）

## 7. 将来フェーズ（ストア公開ロードマップ）

### 7.1 公開までのステップ（合意済み順序）

磨き込み完了後: Capacitor セットアップ → 法務系（プライバシーポリシー・利用規約・免責）→ ストア素材（本番アイコン・スクリーンショット・説明文）→ 審査提出。アプリ名「タロットカード」/ サブタイトル「手軽に本格占い」/ テーマカラー 紫 `#0b0820` + 金 `#f5d76e`。

### 7.2 マネタイズ（方針確定済み・実装は Capacitor 後）

- ¥120 買い切り IAP: 詳細解説フル開放 + 広告完全消失
- バナー広告はハブ画面（トップ・一覧・詳細・履歴）のみ。儀式中は非表示
- インタースティシャルは「左/右」押下後、結果画面遷移直前に挿入。頻度キャップ: 初回 3 回保護 / 以降 50% / 最低 2 分間隔 / 1 日 3 回上限
- リテンション: 連続ログインストリーク、カードコレクション、履歴マイルストーン、21:00 ローカル通知

### 7.3 効果音・BGM

Web Audio 合成方式で暫定実装済みだが、Android + イヤホン環境で再生されない不具合があり本格展開は保留。BGM 制作時に音源ファイル（mp3/m4a）方式へ切り替える。`audio.ts` は残置。

### 7.4 演出拡張

占い師の手・視点演出（Lottie / 動画背景）、小アルカナ・スプレッド対応、AI 解説連携。儀式フローは「フェーズを差し込める」前提の設計を維持する。
