# REQ-005

> カテゴリとすべての回答がそろった詳しく占うで結果の確定が起きたとき、システムは、端末に記録できるかぎり、その占い結果（カード・正逆・キーワード）とその日時にそのカテゴリのカテゴリ名を添えて、占う人の操作なしに占い履歴の先頭へ加えて端末に記録する。

- **分割クラス**:
  - `#category-label` — カテゴリとすべての回答がそろった詳しく占うの結果の確定で、占い結果（カード・正逆・キーワード）にそのカテゴリのカテゴリ名が添えられて、占い履歴の先頭に記録される
- **尽きている根拠**: 通常占い（REQ-001）との違いはカテゴリ名が添わることだけで、先頭への追加・項目の中身・記録の起こり方は REQ-001 のクラスが持つ。回答がそろわないまま儀式へ移った占いはカテゴリ名を添えない側（REQ-001 の #no-category-label）に分けてある。カテゴリの別（5 つ）で振る舞いは変わらないので 1 クラス
- **検証しない**: 無料版では詳しく占うそのものを出さない（BR-005）ので、無料版の構成ではこの要件を起こせない。機能フラグ有効の構成でだけ検証する。カテゴリごとのカテゴリ名の値（用語集とカテゴリの文章の側が持つため）
- **参照先**: `frontend/tests/UC-001-history-record.test.ts::占い履歴への記録: 項目の中身（UC-001）`。詳しく占うの儀式のストップを通した記録は、UC-005・UC-006 の画面のテスト（`frontend/tests/components/ShufflePage.test.tsx` など）が持つ
