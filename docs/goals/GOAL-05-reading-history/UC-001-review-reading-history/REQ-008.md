# REQ-008

> 占い履歴に記録がある間、占う人が占い履歴を開くと、システムは記録されたすべての占い結果を、日時の前後によらず後から記録したものほど先にして一覧で示し、各項目に日時・カード・正逆・キーワードを、カテゴリ名を添えて記録された占い結果にはさらにそのカテゴリ名を示す。

## 検証方針

- **分割クラス**:
  - `#newest-first-order` — 記録されたすべての占い結果が、過不足なく、後から記録したものほど先に並ぶ
  - `#order-ignores-datetime` — 後から記録した項目の日時のほうが前でも、後から記録した項目が先に並ぶ
  - `#orientation-label` — 各項目にその項目の正逆が示される（正位置だけ・逆位置だけ・混在のいずれでも取り違えない）
  - `#image-orientation` — 逆位置で記録された項目の絵は上下逆さに、正位置で記録された項目の絵は正しい向きで示される（BR-003）
  - `#keywords-shown` — 各項目にその項目のキーワードが示される
  - `#datetime-shown` — 各項目にその項目の日時が示される
  - `#category-for-deep` — カテゴリ名を添えて記録された項目には、それぞれのカテゴリ名が示される
  - `#no-category-for-normal` — カテゴリ名を添えずに記録された項目には、カテゴリ名が示されない
- **尽きている根拠**: 一覧の観測は「並び」と「各項目の中身（正逆の語・絵の向き・キーワード・日時・カテゴリ名）」に尽きる。並びは、記録した順と日時の順が一致する場合（#newest-first-order）と食い違う場合（#order-ignores-datetime）に分ける（一致する入力だけでは日時の順に並べる誤りを見分けられない）。カテゴリ名は添えて記録された項目では示す・添えずに記録された項目では示さないの 2 値なので分ける
- **境界の扱い**: 正逆は全件同じ向きの場合も境界として扱う（もう一方の語が湧かないこと）
- **検証しない**: 日時の表示形式（要件の文が形式を定めていないため。示されることだけを #datetime-shown で見る）。上限件数ちょうどの一覧の描画（並びの性質は件数に依らないため）。未来の日時の項目と、無料版で過去の版が書いたカテゴリ名つきの記録の扱い（望む振る舞いが未決のため）。絵の見た目そのもの（実ブラウザでしか確かめられない。jsdom では向きの指定だけを見る）
