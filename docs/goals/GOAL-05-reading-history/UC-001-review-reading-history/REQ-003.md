# REQ-003

> 端末に記録された占い履歴の内容が読めない状態で結果の確定が起きた場合、システムは、端末に記録できるかぎり、読めない内容を捨て、その占い結果 1 件だけからなる占い履歴を記録する。

## 検証方針

- **分割クラス**:
  - `#unreadable-then-record` — 記録内容が読めない（JSON として壊れている／配列でない）状態で結果が確定すると、読めない内容が捨てられ、その占い結果 1 件だけの占い履歴になる
- **尽きている根拠**: 「読めない」は JSON として解釈できない場合と、解釈できても占い履歴の形（配列）でない場合に尽きる。どちらも捨てて 1 件から作り直すという同じ振る舞いなので 1 クラスにまとめ、2 つの入力をどちらもテストで通す。「端末に記録できるかぎり」の外（端末へ書けない）は REQ-004 に分けてある
- **検証しない**: 配列ではあるが項目の形が崩れている記録内容（「読めない」に含めるかを要件の文が定めていないため）
- **参照先**: `frontend/tests/UC-001-history-record.test.ts::占い履歴への記録: 記録内容が読めないとき（UC-001）`
