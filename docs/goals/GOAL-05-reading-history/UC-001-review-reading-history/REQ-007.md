# REQ-007

> 占い履歴が空である間、占う人が占い履歴を開くと、システムは履歴がないことを示してそこから占いを始められるようにし、占う人がそこから占いを始めたときは前の占い結果と前に持ち込んだカテゴリと回答を引き継がずに占い状態を idle にして、通常占いとして占うことを思い浮かべる段階から儀式を始める。

- **分割クラス**:
  - `#empty-message` — 占い履歴が空のとき、開くと履歴がないことが示され、カードの項目は示されない
  - `#start-from-empty` — 占い履歴が空のとき、示された画面から占いを始められる（儀式へ移る）
  - `#start-discards-previous` — 前の占い結果と、前に儀式へ持ち込んだカテゴリと回答が残っていても、履歴なしの表示から占いを始めた時点で占い状態が idle になり、どれも引き継がず、通常占いとして占うことを思い浮かべる段階から儀式が始まる
- **尽きている根拠**: 空の占い履歴を開いたときに求められる観測は「履歴がないことを示す」と「占いを始められる」の 2 つで、片方だけが壊れうるので分ける。始めるときはさらに、前の回の残り（占い結果・持ち込んだカテゴリと回答）が有るか無いかの 2 値で尽きる（無いときは `#start-from-empty`、有るときは `#start-discards-previous`）。読めない記録内容による空は REQ-009、全削除の後の空は REQ-011 に分けてある
- **検証しない**: 履歴がないことを示す文言の言い回し（画面の文言は用語集と画面の側が持つため）。前の回に質問の途中まで答えた回答だけが残っている場合（質問の途中の回答は詳しく占うを終えた時点で残らない — REQ-038 の方針と同じ理由 — ので、残った状態を外から作れない）。初期化後の個々の値（SSOT は BR-002 が指す `reset` の初期値で、テストは idle・占い結果なし・持ち込みなしの 3 点だけを見る）
