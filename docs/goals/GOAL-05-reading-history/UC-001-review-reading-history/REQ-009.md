# REQ-009

> 端末に記録された占い履歴の内容が読めない場合、占う人が占い履歴を開くと、システムは占い履歴が空であるときと同じく履歴がないことを示し、そこから占いを始められるようにする。

## 検証方針

- **分割クラス**:
  - `#unreadable-content` — 記録内容が読めない（JSON として壊れている／配列でない）とき、占い履歴は空として読まれる
  - `#unreadable-shows-empty` — 記録内容が読めないとき、開いた占い履歴が履歴がないことを示し、そこから占いを始められる
- **尽きている根拠**: 「読めない」は JSON として解釈できない場合と配列でない場合に尽き、どちらも空として扱う同じ振る舞い。読み出しの結果と画面の示し方は別に壊れうるので分ける
- **検証しない**: 配列ではあるが項目の形が崩れている記録内容（「読めない」に含めるかを要件の文が定めていないため）
- **参照先**: `frontend/tests/history.test.ts::占い履歴（仕様書 v3 §4.3）`
