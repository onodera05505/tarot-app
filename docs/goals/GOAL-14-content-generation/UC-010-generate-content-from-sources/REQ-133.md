# REQ-133

> 運営者が検査を実行したときに、編集元から生成し直した結果がカードまたは詳しく占うの生成物と一致しない場合、システムは検査を通さず、一致しない生成物と違っている箇所を示す。

## 検証方針

- **分割クラス**:
  - `#in-sync-passes` — 編集元から生成し直した結果がカード・詳しく占うの生成物と一致していれば検査を通す（不一致の検出が空振りでないことの対照）
  - `#cards-source-newer` — カードの編集元を直した後に生成していない（カードの生成物が編集元より古い）
  - `#cards-output-edited` — カードの生成物を手で直した
  - `#deep-output-mismatch` — 詳しく占うのカテゴリの生成物が編集元から生成し直した結果と一致しない（編集元が先・生成物の手直しの両方）
- **尽きている根拠**: 文の条件「一致しない」は、生成物（カード・詳しく占う）× 食い違いの作り方（UC-010 の表の行: 編集元を直した後に生成していない・生成物を手で直した）で尽きる。カードは作り方で 2 クラスに分け（運営者の誤りが違い、示される箇所の新旧が逆になる）、詳しく占うは生成物が複数ファイルでも観測が同じなので 1 クラスにまとめた。一致する場合を対照として 1 クラス置く。どのクラスでも「終了コード」「標準エラー出力に一致しない生成物の名前と箇所」「比べる先の生成物が変わらない」（UC-010 の失敗時の事後条件、CLAUDE.md の「生成物の同期の検査」の行）を観測する。
- **境界の扱い**: 食い違いの最小は 1 語。編集元と生成物の両方に現れる 1 語だけを変え、それ以外は実物の写しのまま。
- **検証しない**: 一致しない生成物以外（一致している生成物）を標準エラー出力に出さないこと（要件は「一致しない生成物を示す」とだけ言い、一致した生成物に触れるかを決めていない）。「箇所」の書式そのもの（行の文言か行番号のどちらかが現れれば箇所と読む）。生成物が揃っていないこと（ファイルの欠け・枚数・字数）は REQ-092。編集元の書式が崩れているときの検査は UC-010 の表で `?` のため。
