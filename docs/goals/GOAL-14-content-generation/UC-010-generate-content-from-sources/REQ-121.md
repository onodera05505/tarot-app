# REQ-121

> カードの編集元が、カードの見出しの書式が崩れている、決められた番号の外のカードがある、同じカードが重複している、カードの枚数が揃わない、必須の文章が空である、のいずれかに当たる場合、システムはカードの内容の生成を失敗させてその理由を示し、どの生成物も書き換えない。

## 検証方針

- **分割クラス**:
  - `#card-heading-broken` — カードの編集元でカードの見出しの書式（`## NN - 日本語名 (English Name)`）が崩れている
  - `#card-number-outside-set` — カードの編集元に決められた番号（00〜21）の外のカードがある
  - `#card-number-duplicated` — カードの編集元に同じカード（同じアルカナ番号）が 2 回以上ある
  - `#card-count-short` — カードの編集元のカードの枚数が決められた枚数（22）に揃わない
  - `#card-required-text-empty` — カードの編集元で必須の文章（正逆のキーワード・正逆の解説文）が空、または必須の行や区切りが欠けた結果として空である
- **尽きている根拠**: 文の条件は 5 つの論理和で、壊し方が異なるので 1 つずつクラスにした。どのクラスでも「終了コード 0 以外で失敗して標準エラー出力に理由を示す」と「書き出し先のどのファイルも書き換えない」の両方を観測する（CLAUDE.md の生成の行）。書式どおりの編集元で書き出し直すことは REQ-090。
- **境界の扱い**: 決められた番号の最大の 1 つ上（22）が境界。最小の 1 つ下は見出しの書式（2 桁の番号）で表せないので、代わりに 2 桁の外れた番号で見る。枚数は 1 枚足りない（21）と 0 枚を見る（多い側は、番号の外か重複なしに 23 枚を作れないので `#card-number-outside-set` か `#card-number-duplicated` に帰着する）。重複は 23 枚になる場合と 22 枚のまま別の番号が欠ける場合の両方を見る。
- **検証しない**: 分量が目安を外れているカードの編集元は、UC-010 の状態表で `?`（振る舞いが決まっていない）のため。同じ名前で番号が違うカードは、「同じカード」をアルカナ番号で読むため重複に当たらない（名前の重複は要件が決めていない）。理由の文言そのもの（要件は「理由を示す」とだけ言い、文言を決めていない）。
