# REQ-093

> 詳しく占うの編集元が、構造（見出し・必須の行・区切り・質問と選択肢の数）が崩れている、決められた集合の外のカテゴリを名乗っている、回答別補足が選択肢の一部にだけある、回答別補足を持たないのに回答別アドバイスが歯抜けである、カードの枚数が揃わないか必須の文章が空である、同じカードが重複している、のいずれかに当たる場合、システムはその生成を失敗させてその理由を示し、どの生成物も書き換えない。

- **分割クラス**:
  - `#deep-structure-broken` — 詳しく占うの編集元で見出し・必須の行・区切りが崩れている
  - `#deep-question-choice-count` — 詳しく占うの編集元で質問と選択肢の数が決められた数でない
  - `#deep-category-outside-set` — 詳しく占うの編集元が決められたカテゴリの集合の外のカテゴリを名乗っている
  - `#deep-supplement-partial` — 詳しく占うの編集元で回答別補足がカテゴリの選択肢の一部にだけある
  - `#deep-advice-gapped` — 詳しく占うの編集元が回答別補足を持たないのに、回答別アドバイスが歯抜けである
  - `#deep-card-missing-or-empty` — 詳しく占うの編集元でカードの枚数が揃わないか必須の文章が空である
  - `#deep-duplicate-card` — 詳しく占うの編集元で同じカードが重複している
- **尽きている根拠**: 文が論理和で挙げる条件を 1 つずつクラスにした（構造だけは、見出し・必須の行・区切りの崩れと、質問と選択肢の数とで壊し方が異なるので 2 つに割った）。UC-010 の状態表で「詳しく占うの文章を生成する」の列が REQ-093 を当てる行とも一致する。どのクラスでも「失敗して理由を示す」と「どの生成物も書き換えない」の両方を観測する。カードの編集元の崩れは REQ-121、ジャンル語は REQ-094 が持つ。
- **検証しない**: 状態表が `?` とする入力（すべての選択肢に回答別補足があるうえにカードに回答別アドバイスも書かれている、カテゴリが 1 つも無い、同じカテゴリを複数の編集元が名乗っている、分量が目安を外れている）は振る舞いが決まっていないため。未定義の質問や選択肢を指す入力は、識別子を編集元に書かず生成が付けるので編集元から作れないため（状態表の「不可」）。
- **参照先**: なし（既存のテスト無し。全クラス未被覆。生成を実行すると実物の生成物が書き換わるため、書き出し先を実物から切り離す手段が決まるまで、生成を実行するテストは置いていない）
