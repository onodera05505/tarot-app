# REQ-097

> 運営者が検査を実行したとき、システムはカードと裏面のすべてに原本とサムネイルがあることを確かめ、すべてあるときに限り検査を通し、無いものがあれば無いものを示す。

## 検証方針

- **分割クラス**:
  - `#original-missing` — カード（22 枚）と裏面のすべてに原本があることを確かめ、無いものがあれば検査を通さず無いものを示す
  - `#thumb-missing` — カード（22 枚）と裏面のすべてにサムネイルがあることを確かめ、無いものがあれば検査を通さず無いものを示す
- **尽きている根拠**: 文の条件は対象（カード・裏面）× 種類（原本・サムネイル）で、「すべてあるときに限り通す」は原本がすべてあることとサムネイルがすべてあることの積。テストは対象をすべてなめるので、対象ではなく種類でクラスを割った。検査はこのテスト群そのものなので、各クラスのテストが通ることが「すべてある」側、落ちることが「無いものがある」側の現れで、UC-011 の状態表で REQ-097 が当たる 3 行（すべて揃っている・サムネイルが無い・原本が無い）を同じテストが担う。
- **検証しない**: 検査が違反を見逃さないこと（原本やサムネイルを欠いた状態を与えて検査が落ち、無いものが示されること）は確かめない。検査はこのテスト群そのもので実物のファイルを読むため、検査の検査は持たず、各アサーションの意味はレビューで見る（REQ-092 と同じ理由。R-901）。どのカードも指さない原本・サムネイルが余分にあること（文の対象外。状態表で `?`。OQ-29-4）。原本とサムネイルの中身の対応（原本を差し替えてサムネイルを生成し直し忘れた状態）は実在しか見ないため拾わない（状態表で `?`。ADR-0007、OQ-29-2）。
