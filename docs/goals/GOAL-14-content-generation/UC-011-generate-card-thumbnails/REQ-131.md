# REQ-131

> サムネイルの生成が、画像として読めない原本があることを含むいずれかの理由で途中で失敗した場合、システムは失敗の理由を示し、どのサムネイルも書き換えない。

## 検証方針

- **分割クラス**:
  - `#unreadable-original-fails` — 画像として読めない原本が混じっていると、生成は終了コード 0 以外で失敗して標準エラー出力に理由を示し、前からあるサムネイルも含めて書き出し先のどのサムネイルも書き換えない（読める原本の分も書き出さない）
  - `#unwritable-thumbnail-fails` — 書き出し先の一部に書けない（サムネイルと同名のディレクトリがある）と、生成は失敗して理由を示し、ほかの原本のサムネイルも書き換えない
- **尽きている根拠**: 文の「いずれかの理由で途中で失敗」は、原本を読む側の失敗と、サムネイルを書く側の失敗に尽きる（生成が触るのはこの 2 つのファイルだけ。CLAUDE.md の生成の行）。どちらも「失敗して理由を示す」と「どのサムネイルも書き換えない」の両方を観測し、後者は途中までの書き出しが残らないこと（部分適用なし。UC-011 の事後条件の失敗時）を含む。
- **検証しない**: 画像処理の道具（Pillow）が無い環境（UC-011 の状態表で `?`。テストはその環境では skip する）。失敗の理由の文言そのもの（要件は文言を決めていない）。カードが指す原本や裏面の原本が無い状態での生成（状態表で `?`）。
