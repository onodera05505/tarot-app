# REQ-087

> 本番の版で報告先が設定されているとき、端末で予期しないエラーが起きたら、システムはそのエラーをエラー監視サービスへ報告する。

## 検証方針

- **分割クラス**:
  - `#starts-with-reporter` — 本番の版で報告先が設定されているとき、報告先を渡してエラー監視サービスへの報告を始める（契約の init が呼ばれる）
  - `#keeps-default-handlers` — 報告を始めるときに契約の integrations へ手を入れても（REQ-130 で訪問の記録を外す）、既定の一覧のほかの項目（描画の外のエラーを捉える手を含む）はすべて残る
  - `#reports-render-error` — 描画中に予期しないエラーが起きたとき、それを報告する（契約の errorBoundary が捉える）
  - `#reports-non-render-error` — 描画の外で予期しないエラーが起きたとき、それを報告する
- **尽きている根拠**: 前提条件（本番・報告先あり）の成立と、エラーが起きる場所（描画中・描画の外。UC-009 の状態表の 2 列）で尽きる。前提が成り立たない側は REQ-088 が持つ。`#keeps-default-handlers` は、契約の init が integrations を必須にしたことで「報告する」が既定の一覧の残り方に依るようになったために置く（契約の examples.ok の一覧 = 既定の一覧から訪問の記録を除いたもの）。
- **検証しない**: 報告が実際にエラー監視サービスに届き、運営者が見られること（外部サービスの責務で、配信された本番の版でしか確かめられない）。通信なしでエラーが起きた場合（状態表で `?`、溜めて後で送る分岐が無い）。
- **参照先**: `frontend/tests/UC-009-error-report-release.test.ts::本番の版・報告先ありでアプリを開いたときに報告へ添えるもの・送らないもの（UC-009）`（`#keeps-default-handlers`。ほかの 3 クラスは未配置）
