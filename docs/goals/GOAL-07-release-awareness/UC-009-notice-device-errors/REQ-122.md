# REQ-122

> 本番の版で報告先が設定されている間、システムは性能の計測と操作の記録をエラー監視サービスへ送らない。

## 検証方針

- **分割クラス**:
  - `#no-performance-measurement` — 本番の版で報告先が設定されているとき、性能の計測を送らない設定で報告を始める（契約の init の性能の計測の送信率）
  - `#no-operation-recording` — 本番の版で報告先が設定されているとき、操作の記録を常時もエラーが起きたときも送らない設定で報告を始める（契約の init の操作の記録の送信率 2 つ）
- **尽きている根拠**: 文が送らないと言う対象は性能の計測と操作の記録の 2 つで、互いに独立に壊れうる。操作の記録の「常時」と「エラーが起きたとき」は同じ対象の送らなさなので 1 クラスにまとめた。状態は「本番の版・報告先あり」の 1 行（UC-009 の状態表の「アプリを開く」）で、報告先なしの側は報告そのものを始めないので REQ-088 が持つ。
- **検証しない**: 実際にエラー監視サービスへ何も届かないこと。外部サービスを通してしか確かめられないため（`docs/verification/GLOBAL.md` の配信・エラー監視の行）。アプリの側の観測は、報告を始めるときに渡す設定までとする。
- **参照先**: 未配置（この要件を観測する既存のテストは無い。アプリの入口を起動するテストは、テストの設定がビルド時にだけ存在する保持の仕組みのモジュールを解決できず、設定を足すまで書けない）
