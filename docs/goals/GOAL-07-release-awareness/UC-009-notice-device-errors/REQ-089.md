# REQ-089

> エラーの表示中に占う人がトップへ戻るを選んだとき、システムはアプリを開き直し、前の占い結果も儀式へ持ち込んだカテゴリと回答も残さずに占い状態を idle にしてトップを示す。

## 検証方針

- **分割クラス**:
  - `#reload-to-top` — エラーの表示中にトップへ戻るを選ぶと、アプリが開き直され、トップの経路に移る
  - `#nothing-carried-over` — 前の占い結果や儀式へ持ち込んだカテゴリと回答が残っているときにエラーの表示中からトップへ戻ると、開き直したあとはどれも残らず、占い状態が idle である
- **尽きている根拠**: 状態は「エラーの表示中」、事象は「トップへ戻るを選ぶ」の 1 組だけで、UC-009 の状態表でもこの 1 セルに限られる。観測点は「開き直してトップを示す」ことと「開き直したあとに何も残っていない」ことの 2 つで、片方だけが壊れうる（開き直さずにトップへ移るだけだと、前の占い結果と持ち込んだカテゴリと回答が残る）ので分ける。
- **検証しない**: 開き直した後に本物のブラウザでトップが描画されること（実際の再読み込みは本物のブラウザでしか起きないため）。`#nothing-carried-over` は、開き直しでアプリの状態が作り直されることに依り、jsdom では開き直しが起きないので、テストの環境では観測できない（クラスは宣言し、未被覆とする）。
