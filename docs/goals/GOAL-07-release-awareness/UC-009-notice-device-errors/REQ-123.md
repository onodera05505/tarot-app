# REQ-123

> 本番の版で報告先が設定されている間、システムはエラー監視サービスへの報告を、利用者の情報を既定で送る設定を無効にして行う。

## 検証方針

- **分割クラス**:
  - `#default-user-info-disabled` — 本番の版で報告先が設定されているとき、利用者の情報を既定で送る設定を無効にして報告を始める（契約の init の該当の設定）
- **尽きている根拠**: 文が言う設定は 1 つで、値は無効の 1 通り（設定を渡さずに SDK の既定へ任せるのは、契約が必須かつ無効と決めているので同じクラスの中の壊れ方）。状態は「本番の版・報告先あり」の 1 行（UC-009 の状態表の「アプリを開く」）で、報告先なしの側は報告そのものを始めないので REQ-088 が持つ。
- **検証しない**: 設定を無効にしても、エラー監視サービスが実際に受け取る情報（接続元から推定される情報など、サービス側の設定に依るもの）。配信した本番の版と外部サービスを通してしか確かめられないため（`docs/verification/GLOBAL.md` の配信・エラー監視の行）。アプリの側の観測は、報告を始めるときに渡す設定までとする。
- **参照先**: `frontend/tests/UC-009-error-report-init.test.ts` の describe「アプリを開いたときのエラー監視サービスへの報告の始め方（UC-009）」の「本番の版・報告先あり」
