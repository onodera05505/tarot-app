# REQ-130

> 本番の版で報告先が設定されている間、システムは訪問の記録をエラー監視サービスへ送らない。

## 検証方針

- **分割クラス**:
  - `#no-browser-session` — 本番の版で報告先が設定されているとき、報告を始める設定の integrations（関数で渡すなら既定の一覧に適用した結果）に、訪問の記録を送る項目（契約の not const の BrowserSession）が無い
- **尽きている根拠**: 文が送らないと言う対象は訪問の記録の 1 つで、契約の init では integrations の各項目の名前が BrowserSession でないことの 1 条件に写る。渡し方（一覧を直接渡す・既定の一覧に関数で手を入れる）は契約の説明で同じ結果の一覧に帰着するので分けない。状態は「本番の版・報告先あり」の 1 行で、報告先なしの側は REQ-088 が持つ。既定の一覧のほかの項目が残ることは REQ-087 の `#keeps-default-handlers`。
- **検証しない**: 実際にエラー監視サービスへ訪問の記録が届かないこと（外部サービスを通してしか確かめられない。`docs/verification/GLOBAL.md` の配信・エラー監視の行）。integrations を渡さずに SDK の既定へ任せる状態は、契約が integrations を必須にしているので同じクラスの中の壊れ方として同じテストが落とす。
- **参照先**: `frontend/tests/UC-009-error-report-release.test.ts::本番の版・報告先ありでアプリを開いたときに報告へ添えるもの・送らないもの（UC-009）`
