# REQ-082

> 保持の仕組みを登録できたホーム画面またはブラウザのアプリを開いたとき、前面に戻したとき、および開いたまま一定時間が経つごとに、システムは Web 配信元へ問い合わせ、配信元の版が稼働中の版と同じなら稼働中の版のまま動き続ける。

## 検証方針

- **分割クラス**:
  - `#queries-on-open` — 開いて仕組みの登録が済んだとき、Web 配信元に問い合わせる（契約の registrationUpdate を呼ぶ）
  - `#queries-on-foreground` — 前面に戻したとき、Web 配信元に問い合わせる
  - `#queries-on-interval` — 開いたまま一定時間が経つごとに、Web 配信元に問い合わせる
  - `#same-version-keeps-running` — 問い合わせの結果、配信元の版が稼働中の版と同じなら、入れ替えも開き直しも起きず稼働中の画面のまま動き続ける
- **尽きている根拠**: 問い合わせのきっかけは要件の文が挙げる 3 つ（開く・前面に戻す・一定時間の経過）で尽き、結果が「同じ版」の場合がこの要件、「新しい版」は REQ-083、「届かない」は REQ-084 が持つ。
- **境界の扱い**: 「一定時間」の値は要件にも契約にも無い。テストは値を固定せず、時間の経過ごとに問い合わせが繰り返されることだけを見る（値を決めるなら要件の側で決める）。
- **検証しない**: 本物の Web 配信元との版の比較そのもの（本物のブラウザの保持の仕組みが行う）。仕組みの登録が問い合わせに使う登録を渡さない場合（契約の例 noRegistration）の振る舞いは要件に無いため。
- **参照先**: 未配置（この要件を観測する既存のテストは無い）
