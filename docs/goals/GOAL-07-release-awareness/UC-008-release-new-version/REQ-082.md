# REQ-082

> 保持の仕組みを登録できたホーム画面またはブラウザのアプリを、新しい版へ入れ替わっている最中でないときに開いたとき、前面に戻したとき、および開いたまま一定時間が経つごとに、システムは Web 配信元へ問い合わせ、配信元の版が稼働中の版と同じなら稼働中の版のまま動き続ける。

## 検証方針

- **分割クラス**:
  - `#queries-on-open` — 開いて保持の仕組みを登録できたとき（契約の onRegisteredSW が問い合わせに使う登録を渡したとき）、Web 配信元に問い合わせる（契約の registrationUpdate を呼ぶ）
  - `#queries-on-foreground` — 保持の仕組みを登録できたアプリを前面に戻したとき、Web 配信元に問い合わせる
  - `#queries-on-interval` — 保持の仕組みを登録できたアプリを開いたまま一定時間が経つごとに、Web 配信元に問い合わせる
  - `#same-version-keeps-running` — 問い合わせの結果、配信元の版が稼働中の版と同じなら、入れ替えも開き直しも起きず稼働中の画面のまま動き続ける
- **尽きている根拠**: 前提は「保持の仕組みを登録できた」かつ「新しい版へ入れ替わっている最中でない」。その中で、問い合わせのきっかけは要件の文が挙げる 3 つ（開く・前面に戻す・一定時間の経過）で尽き、結果が「同じ版」の場合がこの要件、「新しい版」は REQ-083、「届かない」は REQ-084 が持つ。前提が成り立たない側は、ネイティブのアプリを REQ-017 が持ち、登録できていないブラウザと入れ替わっている最中は下の「検証しない」。
- **境界の扱い**: 「一定時間」の値は要件にも契約にも無い。テストは値を固定せず、時間の経過ごとに問い合わせが繰り返されることだけを見る（値を決めるなら要件の側で決める）。
- **検証しない**: 本物の Web 配信元との版の比較そのもの（本物のブラウザの保持の仕組みが行う）。保持の仕組みを登録できていないブラウザ（仕組みを持たない、または契約の例 noRegistration のように問い合わせに使う登録が渡らない）は要件の条件の外で、UC-008 の状態表でも `?` の行のため。新しい版へ入れ替わっている最中の開く・前面に戻す・一定時間の経過も、要件の条件の外で、状態表で `?` のため。
- **参照先**: 未配置（この要件を観測する既存のテストは無い。アプリの入口を起動するテストは、テストの設定がビルド時にだけ存在する保持の仕組みのモジュールを解決できず、設定を足すまで書けない）
