# REQ-080

> 運営者が新しい版を出し、その版が検査をすべて通ったとき、システムはその版を Web 配信元へ配り、配信元の版をその版にする。

## 検証方針

- **分割クラス**:
  - `#deploys-after-checks` — 配る手順が、検査の 4 段（仕様の書式、仕様とコードとテストの対応、テスト、本番ビルド）がすべて通った後にだけ実行される順序で宣言されている
- **尽きている根拠**: アプリ側から観測できるのは配る手順の宣言の順序だけで、それが「検査が通ったときだけ配る」ことの唯一の現れである。端末上のアプリの版は UC-008 の状態表のどの行でもこの要件に影響しない（版を出す列は端末に依らない）。
- **検証しない**: 実際に Web 配信元の版がその版に変わること。配信の経路（CI と配信元）を通してしか確かめられないため（人はトップのビルド識別子で確かめる。`docs/verification/GLOBAL.md` の配信の行）。前の版がまだ届かないうちに次の版を出した場合の配信元側の扱い（配信元の責務）。
- **参照先**: 未配置（この要件を観測する既存のテストは無い）
