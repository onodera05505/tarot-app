# REQ-083

> 保持の仕組みを登録できたホーム画面またはブラウザのアプリが新しい版へ入れ替わっている最中でないとき、問い合わせで Web 配信元に新しい版があると分かったら、システムは占う人の操作なしに新しい版へ入れ替わる。

## 検証方針

- **分割クラス**:
  - `#swap-without-prompt` — 入れ替えを即時に行う指定で保持の仕組みを登録し（契約の registerSW の immediate）、新しい版が見つかっても占う人に確認を求める表示を出さない
- **尽きている根拠**: アプリ側から観測できる「操作なしに入れ替わる」の現れは、即時の指定での登録と、確認を求める表示が無いことだけで、入れ替えの実行は仕組みの側が行う。この指定は開いた時点で 1 度だけ決まり、新しい版が分かった時点の画面（占いの途中かどうか。UC-008 の状態表の 2 行）に依らないので、占いの途中を別のクラスにしない。
- **検証しない**: 実際に新しい版へ入れ替わること（待機中の版の有効化と開き直し。占いの途中で入れ替わることを含む）は、本物のブラウザの保持の仕組みでしか起きないため。新しい版へ入れ替わっている最中に新しい版があると分かった場合と、保持の仕組みを登録できていないブラウザは、要件の条件の外で、UC-008 の状態表でも `?` のため。
- **参照先**: 未配置（この要件を観測する既存のテストは無い。アプリの入口を起動するテストは、テストの設定がビルド時にだけ存在する保持の仕組みのモジュールを解決できず、設定を足すまで書けない）
