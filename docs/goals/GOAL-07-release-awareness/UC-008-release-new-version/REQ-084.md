# REQ-084

> 保持の仕組みを登録できたホーム画面またはブラウザのアプリが新しい版へ入れ替わっている最中でないとき、問い合わせが Web 配信元に届かなかった場合、システムは占う人にエラーを示さず稼働中の版のまま動き続け、次に開いたとき・前面に戻したとき・一定時間が経ったときに再び問い合わせる。

## 検証方針

- **分割クラス**:
  - `#no-error-shown` — 問い合わせが Web 配信元に届かなくても、占う人にエラーを示さず、稼働中の画面がそのまま使える
  - `#retry-on-reopen` — 届かなかった後、次に開いたときに再び問い合わせる
  - `#retry-on-foreground` — 届かなかった後、前面に戻したときに再び問い合わせる
  - `#retry-on-interval` — 届かなかった後、一定時間が経ったときに再び問い合わせる
- **尽きている根拠**: 前提は「保持の仕組みを登録できた」かつ「新しい版へ入れ替わっている最中でない」（UC-008 の状態表で登録済みの上 3 行。配信元と同じ版か新しい版があるかは、届かないので振る舞いを分けない）。要件の文の観測点は「エラーを示さず動き続ける」と「3 つのきっかけで再び問い合わせる」で、再問い合わせはきっかけごとに別の事象なのでクラスを分ける。届かない理由（通信なし・配信元の不調）は契約の UPSTREAM_UNREACHABLE の 1 つにまとまる。
- **検証しない**: 本物の通信断での問い合わせの失敗の仕方（本物のブラウザと通信環境が要るため）。届かなかったことを運営者が知る手段（要件に無い）。新しい版へ入れ替わっている最中と、保持の仕組みを登録できていないブラウザで問い合わせが届かない場合（要件の条件の外で、状態表で `?` のため）。ネイティブのアプリ（Web 配信元へ問い合わせないので、届かないという出来事が起きない。状態表で不可）。
- **参照先**: 未配置（この要件を観測する既存のテストは無い）
