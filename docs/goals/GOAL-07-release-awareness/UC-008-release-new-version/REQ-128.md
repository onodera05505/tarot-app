# REQ-128

> 保持の仕組みを登録できたホーム画面またはブラウザのアプリで、占う人が占いの途中に Web 配信元に新しい版があると分かったとき、システムは途中の占いを消さずに続けさせ、占いの途中でなくなってから占う人の操作なしに新しい版へ入れ替わる。

## 検証方針

- **分割クラス**:
  - `#defer-in-ritual` — 儀式の中（どの段階でも。占い結果からもう一度占うで儀式へ戻った場合を含む）に新しい版があると分かっても入れ替えず、儀式の画面と指定の途中の山がそのまま続く
  - `#defer-while-drawing` — 占い状態が drawing の間に分かっても入れ替えず、抽選が終わると占い結果がそのまま示される
  - `#defer-while-result-shown` — 占い状態が drawn の占い結果を示している間に分かっても、時間が経っても入れ替えず、占い結果がそのまま示され続ける
  - `#swap-after-reading-ends` — 途中に分かった新しい版へ、占い結果からトップへ戻って占いの途中でなくなった時点で、操作なしに入れ替わる
- **尽きている根拠**: 「占いの途中」は UC-008 の表の前書きで 3 つの状態（儀式の中・占い状態 drawing・占い状態 drawn の占い結果を示している間）の和で、途中かどうかの判定は画面（儀式）と占い状態（drawing・drawn）で別々に壊れうるので状態ごとにクラスを分けた。文の帰結は「途中は消さずに続けさせる」（各状態のクラスで観測）と「途中でなくなってから入れ替わる」（最後のクラス）の 2 つ。途中でなくなる操作は、占い結果のトップへ戻るで代表させる（もう一度占うは儀式へ戻るので途中のまま。`#defer-in-ritual` で見る）。
- **境界の扱い**: 抽選が終わらないまま新しい版が届き、終わってから占い結果でトップへ戻る経路（drawing → drawn → 途中でなくなる）も `#swap-after-reading-ends` に置き、入れ替えが状態の切り替わりでなく途中でなくなった時点にだけ起きることを見る。
- **検証しない**: 実際に新しい版へ入れ替わること（本物のブラウザの保持の仕組みでしか起きない）。儀式の中で儀式の画面を外す（ブラウザの戻る）ことで途中でなくなる経路（儀式を離れたときの占い状態は UC-006 の REQ-114・REQ-125 の持ち分で、ここで重ねない）。新しい版へ入れ替わっている最中と、保持の仕組みを登録できていないブラウザ（要件の条件の外で、状態表で `?`）。
- **参照先**: `frontend/tests/UC-008-swap-timing.test.ts::新しい版があると分かったときの入れ替えの時機（UC-008）` の「占いの途中に新しい版があると分かったとき」
