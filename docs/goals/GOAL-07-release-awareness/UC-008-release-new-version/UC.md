# UC-008 新しい版を配って端末に届いたことを確かめる

## 概要

運営者が新しい版を出し、それが検査を通って Web 配信元から端末へ自動更新で届いたことを、端末に出るビルド識別子で確かめる。

## 事前条件

- 運営者の端末に、ホーム画面またはブラウザで一度開いたアプリが保持されている
- 適用される業務規則: BR-006

## 主シナリオ

1. 運営者が新しい版を出す
2. システムが配る前の検査の 4 段（仕様の書式、仕様とコードとテストの対応、テスト、本番ビルド）を行い、すべて通ったときだけ新しい版を Web 配信元へ配る
3. 運営者が端末でアプリを開く（または前面に戻す）
4. システムが Web 配信元に新しい版の有無を問い合わせ、新しい版があれば運営者の操作なしに入れ替わる（自動更新） → BR-006
5. 運営者がトップを開く
6. システムがトップに稼働中の版のビルド識別子を示す

## 例外系の走査（4 分類）

| 軸 | 該当ステップ | 導出 |
| --- | --- | --- |
| 権限 | 1 | なし（新しい版を出せるのは運営者だけで、アプリ側に判断する権限は無い） |
| 不変条件違反 | 2 | 検査の 4 段のいずれかに落ちる版 → REQ-081 |
| 並行性 | 4 | 占いの途中で新しい版があると分かる → REQ-083（占いの途中でも入れ替わる）。新しい版へ入れ替わっている最中に開く・前面に戻す → 表の `?`。前の版がまだ届かないうちに次の版を出す → REQ-080 |
| 外部依存 | 2, 4 | Web 配信元に問い合わせが届かない → REQ-084。保持の仕組みを登録できていないブラウザ → 表の `?` 行。ネイティブのアプリは配信元に問い合わせない → REQ-017 |

## 事後条件

- 成功時: 運営者が端末のトップで、出した版のビルド識別子を見ている
- 失敗時: いかなる状態変更も残っていない（部分適用なし。検査に落ちた版は配信元に載らず、端末は前の版のまま動く）
