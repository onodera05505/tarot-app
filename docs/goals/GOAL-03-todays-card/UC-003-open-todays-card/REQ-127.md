# REQ-127

> 本日の一枚を示したまま端末の現地時刻の日付が開封した日より後に変わった場合、占う人がアプリを前面に戻したとき、システムは前の日の開封を引き継がず、本日の一枚を未開封として示す。

## 検証方針

- **分割クラス**:
  - `#foreground-after-day-change` — 開封済みを示したまま端末の現地時刻の日付が開封した日より後に変わり、アプリを前面に戻すと、前の日の開封を引き継がず未開封として示される（その新しい日の開封は記録されない）
  - `#same-day-foreground-keeps-opened` — 同じ日のうちにアプリを前面に戻しても、開封済みのカード・カード名・正逆がそのまま示され、記録も変わらない（REQ-023 と矛盾しない側）
- **尽きている根拠**: 前面に戻したときの端末の日付は「開封した日と同じ」か「開封した日より後」かの 2 値で、後の日であれば翌日でも数日後でも同じ振る舞い。日付が変わったのに開封済みを示し続ける壊れ方と、同じ日なのに未開封へ戻す壊れ方は別々に起きうるので 2 クラス
- **境界の扱い**: 日付が変わった直後（翌日 0 時台）が境界点。同じ日の終わり（23 時台）は同じ日の側
- **検証しない**: 前面に戻す操作が無いまま日付が変わる場合（UC-003 の表の `?` 列。望む振る舞いが未決）。開封中に日付が変わって前面に戻す場合（UC-003 の表の `?` セル。進行中の抽選の扱いが未決）。端末の時刻が開封した日より前へ戻された場合（文が後の日だけを定めている）。実ブラウザ・実機の前面復帰そのもの（jsdom では `document.visibilitychange` の発火で起こす）。未開封のまま前面に戻す場合（REQ-022）
- **参照先**: `frontend/tests/components/UC-003-todays-card-foreground.test.tsx::本日の一枚: 示したまま日付が変わりアプリを前面に戻す（UC-003）`
