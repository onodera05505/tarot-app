# 検証方針（全体）

各要件の検証方針は要件ファイル（`docs/goals/**/REQ-nnn.md` の `## 検証方針`）に同居する（R-1002）。
この文書はプロジェクト**全体**で検証しない範囲のみを持つ。

## 検証しない範囲（全体）

| 範囲 | 理由 |
| --- | --- |
| ユースケースごとのシナリオテスト（本物のブラウザでの通し） | ブラウザの通しテストの仕組みが無く、`traceconfig.json` の `tests.system` は未設定（C15 は skip）。持つかどうかは `OPEN-QUESTIONS.md` の OQ-10 で決める。それまでの通しの確認は本人の実機レビュー |
| 画面（本物のブラウザ × 状態 × 幅 × 配色） | 状態の行列もスクリーンショットの比較も無い（`docs/検査と門.md` §2 で「穴」）。自動の検査は jsdom の描画までで、組版・見た目は人の目と実機で見る |
| 使いやすさ | 本人の実機レビューのみで、機械の判定手段が無い（`docs/検査と門.md` §2 で「穴」） |
| ネイティブのアプリの実行環境（Capacitor / Android） | APK が未ビルドで、実機で見る項目（直接パスで開く・効果音・セーフエリアとステータスバーの色）は `brain/PREMISES.md` の未決に工程として残っている（`docs/検査と門.md` §2 で「穴」、§1 #8） |
| 効果音の鳴り方（iOS で鳴らす前の解錠を含む） | テストの実行環境（jsdom）に Web Audio が無く、実機でしか確かめられない（`docs/検査と門.md` §1 #14） |
| 演出の見た目（積み直し後のカードの重なり順・小さい端末でのタップ対象の位置） | 見た目と端末の大きさに依り、実機でしか確かめられない（`docs/検査と門.md` §1 #15・#16） |
| 配信・更新の到達と、エラー監視サービス側の受信 | 配信の経路と外部サービスを通してしか起きない。稼働中の版はトップのビルド識別子で人が確かめる。エラー監視サービスのアラート設定と外形監視は未確認（`docs/検査と門.md` §2 の運用の行が「一部」） |
