# App Store 公開手順書（収益化つき）

作成: 2026-08-22。タロットカードアプリを Apple App Store に公開し、
少額の収益化（¥120 買い切り IAP + 広告）を行うまでの手順を、
フェーズ順・役割分担つきでまとめる。方針の土台は要件定義書 v3 §7
（Web → PWA → **Capacitor** でラップ、React Native への書き直しはしない）。

## 役割分担の原則

- **あなた（ユーザー）**: 外部アカウントの作成・契約・支払い・審査対応の
  本人確認類（Apple Developer / AdMob / RevenueCat / 銀行・税務情報）
- **私（Claude）**: コード・設定・文章（ポリシー文面の下書き・ストア説明文・
  審査向けメモ）・ビルド関連の作業すべて

## 費用の全体像

| 項目 | 費用 | 備考 |
|---|---|---|
| Apple Developer Program | 年会費 約 1.5 万円 | 申込画面で最新額を確認。**これだけは公開に必須** |
| AdMob（広告） | 無料 | Google アカウントで開設。収益は入金される側 |
| RevenueCat（IAP 管理、採用する場合） | 無料枠 | 月次課金収益が一定額を超えるまで無料 |
| Sentry / Cloudflare / GitHub | 現状の無料枠のまま | 変更なし |

収益の現実的な期待値: 個人開発の占いアプリは「サーバー費ゼロ運用なので
赤字にならない」を勝利条件にするのが健全。年会費を IAP 約 125 件 or
広告収益で回収できれば十分成功、という温度感で設計する。

## フェーズ 0: アカウントと前提（あなたの作業が主）

1. **Apple Developer Program 加入**（あなた）
   - https://developer.apple.com/programs/ から個人として登録
   - Apple ID は個人開発用（onodera.development 系）に統一するのを推奨
     （Cloudflare・GitHub と同じく、社用と混ぜない）
   - 加入承認まで最大 48 時間程度
2. **App Store Connect で契約・税務・口座の登録**（あなた）
   - 「Paid Applications 契約」への同意 + 銀行口座 + 税務情報（W-8BEN 相当は
     画面の案内に従うだけ）。**IAP を売るには必須**。広告のみなら不要だが
     今回は両方やるので最初に済ませる
3. **AdMob アカウント開設**（あなた）— アプリ登録は Capacitor 化後でよい
4. 開発環境（このマシン）: Xcode を App Store からインストール（無料・
   数十 GB あるので時間に余裕のあるときに）。CocoaPods は Capacitor
   セットアップ時に私が入れる

## フェーズ 1: Capacitor 化（私の作業が主）

ゴール: いまの Web アプリがそのまま iPhone のネイティブアプリとして起動する。

1. パッケージ導入と初期化
   ```
   pnpm add @capacitor/core
   pnpm add -D @capacitor/cli
   pnpm exec cap init  # appId: com.onodera.tarot など（後から変えにくいので最初に確定）
   pnpm add @capacitor/ios && pnpm exec cap add ios
   ```
2. ビルド連携: `pnpm build` → `cap sync ios` → Xcode でシミュレータ起動
3. **アプリ内配信の設計判断（重要）**: ネイティブ版は Web と違い、
   アセットをアプリに同梱して App Store 審査経由で更新するのが標準。
   - PWA の Service Worker / 自動更新機構は**ネイティブ内では無効化**する
     （二重更新の事故防止。Web 版はいまのまま）
   - テキスト差し替えのたびに審査を通すのは重いので、頻繁に直したくなる
     カードテキストの「リモート更新」は将来課題として一旦見送り
     （まずは同梱で公開し、必要になったら検討）
4. ネイティブらしさの最低ライン対応:
   - セーフエリア（ノッチ）対応の CSS 点検 / ステータスバー配色
   - スプラッシュスクリーン + アプリアイコン（`@capacitor/assets` で生成）
   - 戻るスワイプ等の挙動確認
5. 保留していた **ハプティクス**（振動フィードバック。カード操作時）と
   **効果音の音源ファイル化**はここで入れるのが効率的（任意。審査には不要）
6. 実機テスト: あなたの iPhone を USB 接続 → Xcode から直接インストール
   （Developer アカウントがあれば TestFlight 配信も可能）

## フェーズ 2: 収益化の実装（設計判断 → 仕様書改訂 → 実装）

確定済みの方針（v3 §7.2）:
- **¥120 買い切り IAP**: 詳細解説フル開放 + 広告完全消失
- **バナー広告**: ハブ画面（トップ・カード一覧/詳細・履歴）のみ。儀式中は非表示
- **インタースティシャル**: 「左/右」押下後、結果画面遷移の直前。
  頻度キャップ: 初回 3 回保護 / 以降 50% / 最低 2 分間隔 / 1 日 3 回上限

着手前に決めること（仕様書 v3.3 として採否を取る）:
1. **無料と有料の境界線**: 現在「詳しく占う」は全機能無料。
   「詳細解説フル開放」を何に対応させるか——例:
   - 案 A: 詳しく占うの結果のうち「回答別アドバイス 3 本」を有料側に
     （ベース解釈までは無料で読める。買い切りの価値が明確）
   - 案 B: 詳しく占うは 1 日 1 回無料、2 回目以降は有料
   - 案 C: 機能制限はせず「広告消し」のみを ¥120 の価値にする
2. **IAP の実装方式**: RevenueCat SDK（レシート検証・復元処理込みで楽、
   アカウント 1 つ増える）か、StoreKit 直（依存は減るが実装・検証が重い）。
   推奨は RevenueCat
3. **広告の種別**: パーソナライズ広告は ATT（トラッキング許可ダイアログ）が
   必要。**非パーソナライズ広告のみにすれば ATT 不要**で審査もシンプル。
   収益単価は下がるが、初回リリースは非パーソナライズ推奨

実装項目（決定後）:
- `@capacitor-community/admob` 導入、広告ユニット作成（あなた: AdMob 側）、
  ハブ画面バナー + インタースティシャルの頻度キャップ実装（テスト込み）
- IAP: 商品登録（App Store Connect、あなた）+ 購入・復元フロー実装（私）。
  「購入を復元」ボタンは審査要件なので必須
- 購入状態はローカル保存 + 起動時レシート照会。設定的な画面（購入・復元・
  ポリシーへのリンクを置く場所）をトップに追加

## フェーズ 3: 法務・プライバシー（文面は私が下書き）

1. **プライバシーポリシー**（公開 URL 必須）: 収集するもの（広告 SDK の
   識別子・Sentry のクラッシュ情報・ローカル保存のみの占い履歴）を明記。
   Cloudflare Pages に `/privacy` として同居させる
2. **利用規約 + 免責**: 占いは娯楽であり、医療・法律・投資等の助言では
   ない旨（健康・お金カテゴリを作った今、この免責は特に大事）
3. **App Privacy（アプリのプライバシー「栄養表示」）**: App Store Connect で
   申告。AdMob を入れると「識別子・使用状況データ」等の申告が必要になる。
   SDK 各社の申告ガイドに沿って私が申告内容の一覧を作る → あなたが入力
4. 販売者表示（特商法系）は App Store では Apple が販売者となるため、
   個人の住所公開などは不要（これも Capacitor/ストア経由の利点）

## フェーズ 4: ストア素材（私が下書き → あなたが選定）

- **アプリ名**: タロットカード / **サブタイトル**: 手軽に本格占い（確定済み）
- **本番アイコン**: 現在の 8 点星は暫定。1024×1024 の本番版を作る
  （方向性だけ決めてもらえれば私が SVG で数案作る）
- **スクリーンショット**: 6.7 インチ（iPhone 15 Pro Max 級）必須。
  儀式・結果・詳しく占う・カード解説の 4〜5 枚 + キャッチコピー帯。
  シミュレータで私が撮影 → 帯付き加工まで作る
- **説明文・キーワード・プロモーションテキスト**: 私が下書き
- **カテゴリ**: エンターテインメント / **年齢区分**: 占いは 4+ で可
  （審査質問への回答表を私が用意）

## フェーズ 5: 審査提出

1. App Store Connect でアプリ作成（Bundle ID はフェーズ 1 で確定したもの）
2. TestFlight で最終確認（あなたの実機 + 可能なら家族友人 1〜2 人）
3. 審査提出。占いアプリで注意すべき指摘と対策:
   - **4.2 最小限の機能**: 「ただの Web サイトのラップ」と見られないこと。
     儀式演出・ハプティクス・IAP・オフライン動作が揃っていれば十分戦える
   - **2.1 完成度**: クラッシュ・リンク切れゼロ（Sentry とテストで担保済み）
   - IAP は「復元」導線と価格表示が必須。広告は申告と実装の一致
   - リジェクトされても修正 → 再提出が普通の流れ。1 回で通れば上出来
4. 公開設定は「審査通過後に手動で公開」を推奨（自分のタイミングで出せる）

## フェーズ 6: 公開後の運用

- 更新はアプリ内テキストも含め App Store 審査経由（軽微修正は審査も速い）
- Sentry でクラッシュ監視（現在 Web で有効。ネイティブにも適用）
- 収益・DL 数は App Store Connect / AdMob のダッシュボードで確認
- v3 §7.2 のリテンション施策（ストリーク・カードコレクション・21 時の
  ローカル通知）は公開後のアップデート弾として温存

## 推奨する進行順序と現在地

```
[完了] アプリ本体の充実（詳しく占う 5 カテゴリ・テスト 107 件・自動更新）
  ↓
フェーズ 0: あなた → Apple Developer 加入（承認待ち時間があるので最初に）
  ↓ 並行できる
フェーズ 1: 私 → Capacitor 化・実機起動まで
  ↓
フェーズ 2 の設計判断（無料/有料の境界・広告方式）→ 仕様書 v3.3 → 実装
  ↓
フェーズ 3〜4: 法務文面とストア素材（実装と並行可）
  ↓
フェーズ 5: TestFlight → 審査提出
```

最初のアクションは 2 つ:
1. **あなた**: Apple Developer Program の加入手続きを開始する
2. **私**: フェーズ 1（Capacitor 化）に着手する——ここは既存アプリを
   壊さない追加作業なので、加入承認を待つ間に進められる
