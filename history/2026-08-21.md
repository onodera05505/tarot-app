## 2. 仕様書 v2 と実装の突き合わせ監査（調査のみ、コード変更なし）

**意図:** 仕様書駆動の基準点を作る。長期放置後の再開なので、挙動を変える
前にどこがズレているかを確定させる。

**結論: 仕様書 v2（2026-04-27）は現実装の一次資料として機能していない。**
v2 が「将来フェーズに移管」と明記した多段カット演出を、2026-05-02 の
ユーザー要望で実装済み（intent → shuffling → merging → split3 →
stacking3 → split2 → stacking2 → rotating → orienting → transitioning）。
さらに v2 の除外リストにある履歴（localStorage 100件）・シェア画像生成・
PWA・Sentry も実装済み。アーキテクチャも v2 記載の「backend API」から
「フロント完結（local-only）」へ移行済み（コミット 6bdce81。backend/ は
参照用残置、CI からもデプロイ撤廃済み）。

**確認できた設計判断（覆すときは根拠とセットで）:**
- 「左/右」選択が結果の正逆に反映されないのは**意図的**。コミット 24efef6
  （2026-05-02）に「ユーザー依頼により左右選択は儀式演出のみ、正逆は
  ランダム維持」と明記。退行ではない。カードは「ストップ」押下時点の
  `drawOne()` で確定し、以降の操作は演出（`useReadingStore.setOrientation`
  は定義のみ残存・呼び出しゼロ）
- カードデータは 22 枚完備（正逆キーワード + 詳細解説文 + WebP 画像 22+裏面）。
  「未設定」プレースホルダーは残っていない。生成元は `frontend/data/cards.md`
  → `pnpm gen:cards`

**発見した課題（直さずに記録、次の弾）:**
1. **仕様書 v3 が必要** — 現在の姿（儀式フロー・local-only・履歴/本日の
   一枚/シェア）を「目指すべき形」として書き直さないと仕様書駆動が回らない
2. **ResultPage に「もう一度占う」導線がない** — v2 §5④ の要件で、v3 でも
   残るはずの正当な未実装。再度占うには一度トップへ戻る必要がある
3. **デッドコード群** — `SelectPage.tsx` / `CardSelector.tsx`(+css) /
   `audio.ts` の `playPreview`・`playSelect` / `useReadingStore.setOrientation` /
   `vite.config.ts:53-63` の `/api/cards` workbox ルール / `api.ts` の
   未使用 `_signal` 引数
4. **テスト 0 件** — ロジック濃い箇所（ShufflePage の `ranksAfterStack3/2`、
   `api.ts` の `drawCards`、`history.ts` の 100 件上限、`TodaysCard` の
   日付境界）が全て無検証。CI もビルドのみ
