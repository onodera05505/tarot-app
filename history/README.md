# 編集履歴

このディレクトリはタロットアプリ開発の**編集履歴**を日付ごとに残す場所です。
Git 履歴だけでは追いづらい「その日どんな塊の仕事をしたか」「なぜそうしたか」を
まとめておくためのものです。

## ルール

- ファイル名は **`YYYY-MM-DD.md`**（例: `2026-08-04.md`）
- 各日ログには **作業の塊ごとに見出し** を立てる
- 各見出しには次を含める
  - **意図** — なぜその変更をしたか
  - **主な変更ファイル** — どこを触ったか
  - 必要なら **設計上の判断** や **未解決の宿題**
- 1日に複数のセッションがあれば、同じ日付ファイルに追記する（見出しで分ける）
- 履歴は `git add` して他のコード変更と一緒にコミットする
- **各日のファイルの末尾に還元行を必ず置く**:
  `ブレイン: 参照した型 X / 適用前に確認した値 Y / 追加 Z / 更新 W / 無し（理由）`
  中央ブレイン（`~/.claude/brain/`）へ型を還したか、還さない理由を毎回書く。
  `frontend/tests/history-return-line.test.ts` が 2026-09-11 以降の日付ファイルを検査し、
  無ければ `pnpm test` が落ちる（= CI でデプロイも止まる）。中央の同じ門は
  `python3 ~/.claude/brain/check_return_line.py --root .`

## 更新のタイミング

- そのセッションの作業が一区切りついたとき
- 大きな判断を下したとき（技術選定や仕様変更の合意）
- 未解決課題を積み残したとき（次のセッションで拾えるように）

## 読むタイミング

- **編集作業を始める前** に必ず一連の履歴を読む。
  過去の意図・未解決課題・保留事項を踏まえたうえで次の変更を組み立てる。
